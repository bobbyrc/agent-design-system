# Runtime contract boundary

The frozen instance is `examples/equipment/acceptance.json` (`ui-acceptance/v1`). Executable validation is in `scripts/evidence.mjs`; the schemas below describe record structure. Unknown extra metadata cannot authorize requirements, applicability, review or summary outcomes. The seven IDs and required state/width capture inventory are exact. A machine or visual pass rejects missing or duplicated required state images. No not-applicable conditions are authorized in this revision.

`ui-run/v1` binds source bytes (including verifier, schemas, lockfile and brief), fixture bytes and acceptance bytes separately. Each artifact has path, SHA-256, kind and the same run/source/contract/fixture binding. The local server freezes a map of bytes before launching Chromium and records served hashes. Recheck against the current repository with `npm run evidence:check -- <run.json>`; mutations invalidate evidence. Evidence paths must be regular files under `artifacts/ui-runs/<run_id>/` without symlinks or traversal. Execution assertions carry the same bindings in their JSON bytes; a PASS cannot cite an assertion record containing an error. Recorded runtime exceptions, first-party request failures, or forbidden external requests prevent machine PASS, while genuine FAIL, BLOCKED and authorized not-applicable outcomes remain explicit. The required `review` field is null until review import; when present it must have a path and hash. runtime records must match the current served-source hashes, and capture inventory records must match the exact image paths, hashes, states and encoded PNG widths. Captures must contain complete PNG pixel data. Required captures with duplicate hashes are rejected unless all their states belong to one frozen `capture_equivalence_groups` entry (an array of state-name arrays). Every group must name at least two required captures at the same width, and groups cannot overlap. This permits expected equal pixels, such as a ready loading state and its ordinary queue, without accepting arbitrary reused screenshots. Equal hashes prove equal bytes, not distinct state execution. Duplicate paths or state/width declarations are rejected.

`ui-image-review/v1` must be a real fresh independent review, not copied from an illustrative template. Supply `schema`, `illustrative_only:false`, `run_id`, `source_hash`, `contract_hash`, `fixture_hash`, `reviewer` (identity), `independent_context:true`, `reviewed_at` (ISO timestamp after execution), `images` (exact array of `{path,sha256}` for all image artifacts), `input_evidence_hashes` (exact hashes of every non-image run artifact), `inspection_records` (nonempty references to actual image inspection events), and `findings` (empty allowed).

Each finding has `state`, `region`, `observation`, `consequence`, `severity` (`blocker|major|minor|preference`), `acceptance_condition` and `disposition` (`open|resolved|accepted`). Acceptance requires `rationale` and is limited to minor/preference findings. Open minor findings block until explicitly accepted. Open preference findings do not block. A resolved finding requires a `resolution` rationale, `resolution_evidence` paths pointing to current run artifacts, and a fresh current-artifact review; do not reuse a pre-fix run. Ingest with `npm run evidence:review -- <run.json> <reviewer.json>`. Every contract must contain at least one required check whose method is `independent_actual_image_review`; its ID is reusable and may differ from the equipment example. This method controls the independent review gate and machine-only exclusion. Import validates the complete candidate before writing, then publishes an immutable review copy and atomically replaces the run; failed imports preserve the original run and remove any new review copy. This computes the result; it never invents a review or automates visual approval.

This is builder-writable local bookkeeping, not a protected evaluator. Hashes establish byte identity; they cannot establish that a person/model looked at images, that a claimed reviewer is independent, or that an inspection event is authentic. CI uses the same mutable scripts. A protected evaluator would need separate control of capture, policy and grading. Scope is this authored teaching fixture in standalone Chromium, with no production integration, held-out validity, screen-reader audit, all-host coverage or automatic host enforcement.
