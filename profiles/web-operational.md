# Operational web profile

ID: `web-operational/v1`. Scope: browser interfaces for repeat collection, detail and transactional tasks. Original contextual guidance; effectiveness untested. Load for operational web tasks, not editorial expression or native-platform work. Source IDs: `SP-01`, `SP-03`, `SP-04`, `SP-07` in [provenance](../docs/web-source-provenance.md).

Inspect the project's existing typography, semantics, components, density, routing and content conventions first. A compact workspace may fit repeated scanning; repeat use and preferred density remain assumptions until user evidence supports them. No mandatory palette, radius, font size or desktop layout is supplied. The source pack's optional token specimen is provisional and is not installed as a universal system.

Resolve realistic normal and stress content: stable IDs, long and similar names, dates/timezone/clock, localized labels, empty scope, no matches, stale data, action eligibility, pending, recoverable error and confirmed success. Preserve filters and selected identity across navigation. Define integration honestly: the equipment example is `prototype_mock`, with no production inventory, messaging, fees or offline reconciliation.

## Checks to operationalize

| Area | Project decision and evidence |
| --- | --- |
| Task | Critical user journey plus confirmed store/service outcomes |
| State | Required/conditional state inventory and fixture recipes |
| Responsive | Declared viewports, relevant 320 CSS-pixel reflow, breakpoint neighbors, long content and text enlargement |
| Keyboard | Real Tab/text-entry/task path, visible focus, no trap, meaningful focus after updates |
| Semantics | Native controls/labels, meaningful status updates, actual modal behavior if selected |
| Appearance | Actual images for hierarchy, readability, clipping, density and component grammar |
| Accessibility | State-specific automated findings and triage plus declared manual scope; no blanket conformance claim |
| Freshness | Build, fixture, acceptance hash and artifact hashes tied to each run; affected edits require retest |

Treat task success, accessibility evidence, visual judgment and reproduction fidelity separately. A passing scanner does not prove usability or complete accessibility. A faithful reproduction does not prove a good design. Pixel units and browser checks here do not transfer automatically to iOS, Android or desktop native apps. Unsupported platform work remains outside this increment.
