# Contacts-picker visual-quality evidence

Scope: quality targets for a hypothetical desktop picker that searches for a person, selects them, then uses Invite. This is reference analysis, not a new design or an approval. No target draft or project visual system was supplied.

Evidence: [Refactoring UI public instruction](https://refactoringui.com/), craft instruction; inspected local `before.png` and `after.png` in `/private/tmp/figma-ui-reference-inspection/` on 2026-09-29. Both show Contacts, a search field, five entries, Cancel, and Invite. The supplied source explanation says excessive borders create clutter and offers spacing, background contrast, or shadow as alternatives. That explanation is distinct from the observations and transfer inferences below.

| Quality | Observed change and transferable inference / exclusions | Observable target and discrepancy → correction |
| --- | --- | --- |
| Grouping | Before has full-width rules between rows and surrounding the search region; after removes these and insets the list. Repeated alignment and larger vertical gaps provide separation. **Inference:** proximity can organize this picker without outlining every row. Exclude a universal “fewer borders is better” rule. | Each name, identifying detail, and any marker should read as one row at intended desktop size. **Hypothetical gap:** redundant rules compete with meaningful section boundaries → remove only redundant rules and verify that longer names still remain associated with their details. |
| Search recognition | Before’s search field has an outline and faint shadow; after uses a pale filled rounded surface. Both retain the search icon and placeholder. **Inference:** surface contrast can identify the field. The pictured after does not demonstrate adding shadows. | Search remains visibly distinguishable from results. If removing its outline makes it disappear against the target background, restore sufficient contrast using the project’s established treatment. Exclude the exact gray, radius, font, and dimensions. |
| Row emphasis | Taylor Otwell’s row has a pale full-width background before and an inset rounded background after; its Member label is darker after. **Inference:** localized emphasis can distinguish a row. The images do not establish whether this means hover, focus, or selection; dots are also unlabeled. | Verify actual selection and keyboard focus against the target’s defined behavior. Do not adopt the pale fill or green dots as confirmed selection indicators. |
| Action hierarchy | Invite remains a bright filled button beside text-like Cancel. After separates the footer through a pale background rather than a top rule. | Invite should retain clear action priority, while the footer remains distinguishable from results. Preserve project conventions rather than importing blue or this footer’s height. |

Specific reference discrepancy: Duke Street Studio changes from Team to Member, while three gray dots become green. Preserve actual entity types and statuses when comparing treatments; decorative refinement should not change their meaning.

Evidence limits: after is taller (852 versus 774 pixels at the same 800-pixel width) and spaces rows farther apart. Compare equal-content renders in the same target viewport before accepting the density tradeoff. Neither image demonstrates search results, selection behavior, successful invitations, accessibility, or improved task performance; no user testing is evidenced.
