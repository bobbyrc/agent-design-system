# Primary design guidance evidence

Researched 2026-09-29. Read official page text and indexed official excerpts; did not render or visually inspect screenshots. Recommendations below are synthesis, not a claim that one system proves aesthetic quality.

## Recommendation

For a dense desktop work application, Carbon is the strongest default among these sources: it explicitly distinguishes productive UI typography from expressive web typography, specifies compact table dimensions, and explains how to preserve readable data density. Pair it with NN/G's task-based table criteria and visual composition critique. Fluent is a strong alternative when Microsoft platform conventions or its component stack already govern the product. For native Apple apps, use the current Apple HIG first; for Android/adaptive Material apps, use Material. An established product visual system takes precedence over a new generic default.

| [Carbon: Data table usage](https://carbondesignsystem.com/components/data-table/usage/) and [style](https://carbondesignsystem.com/components/data-table/style/) | Give dense data substantial page width; avoid cramped nested containers and truncation; match header and row height; reserve extra-large rows for two lines; retain hover to aid horizontal scanning. Style dimensions: row heights 24/32/40/48/64 px, 14 px row and column text, semibold column headers. | Directly useful for operational consoles, admin tools, resource lists, and dense desktop comparison tasks. | A component specification does not establish the right columns, user task, or whole-page composition; Carbon explicitly says its table is not a spreadsheet replacement. |
| [Carbon: Type sets](https://carbondesignsystem.com/elements/typography/type-sets/) | Productive UI uses 14 px base text and fixed headings for dense containers; expressive web pages use 16 px base and fluid headings. Compact productive body is 14/18 px; long productive body is 14/20 px. | Particularly strong guidance for choosing density without importing marketing-page typography. | Adopt role relationships and appropriate dimensions deliberately; IBM Plex and IBM styling are not mandatory for another brand. |
| [Fluent 2: Layout](https://fluent2.microsoft.design/layout) | Use proximity to communicate groups, larger spacing to emphasize focal items, alignment to establish predictable scanning, and a 4-unit spacing ramp with optical exceptions such as 2/6/10. | Microsoft-facing productivity UI and consistent cross-platform spacing decisions. | Does not mean all pages should have uniform large gaps; it describes how spacing communicates relationships, not a single page template. |
| [Material: Canonical layout examples](https://m3.material.io/foundations/layout/canonical-examples/overview) | Select a feed, list-detail, or supporting-pane structure based on content/task; adapt its configurations across compact, medium, and expanded breakpoints. Supporting panes separate main content from contextual secondary content. | Android and adaptive multi-pane apps; useful architecture pattern for a list plus inspector. | Layout examples are starting structures, not proof of polished visual execution or a specification for dense tables. | [NN/G: Good Visual Design, Explained](https://www.nngroup.com/articles/good-visual-design/) | Align type and elements to a consistent grid, establish typographic hierarchy, apply color intentionally, and maintain consistency. Gutter width depends on content and purpose. | Best plain-language source here for explaining why composition looks coherent. | Examples are illustrative rather than a benchmark; this research did not visually inspect their screenshots. |
| [NN/G: Five visual design principles](https://www.nngroup.com/articles/principles-visual-design/) | Evaluate scale, hierarchy, balance, contrast, and visual grouping. Relative size and emphasis should communicate importance; proximity should communicate relationship. | Cross-platform critique of a rendered design. | Its small set of size suggestions are heuristics, not strict limits for complex applications or replacements for accessibility checks. |
| [NN/G: Data Tables—Four Major User Tasks](https://www.nngroup.com/articles/data-tables/) | Tables should support finding records, comparing values, inspecting/editing individual records, and acting on records. Aligned adjacent values reduce reorientation and memory burden compared with cards. | Dense workplace UI and deciding whether cards or tables fit the task. | Functional/task evidence; does not supply the complete visual system. |

## Operational implication

A useful quality criterion connects a visible choice to a task: aligned values improve comparison; a stronger heading identifies the current work area; tighter internal spacing and larger inter-group spacing clarify relationships. Check those effects on a rendered artifact with realistic content. A token catalogue, fashionable style, or unrendered component inventory is insufficient evidence that the resulting screen is good.
