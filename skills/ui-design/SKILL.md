# UI design entry

Identify the user task, mode, platform, existing product system, realistic content, and completion outcomes in the existing [brief](../figma-ui/assets/design-brief.md) or its project equivalent. Preserve constraints, settled decisions, and delegated authority. Record consequential choices in the brief or a linked decision record: distinguish observed facts with sources, mechanism-based inferences, and unvalidated assumptions with consequences. Ask only for a material missing decision or authority; proceed on bounded routine assumptions.

## Select one route

- **Original with an existing system:** inspect its surfaces, tokens, components, content and behavior; select applicable patterns within that grammar.
- **Original without a system:** compare a small number of credible directions using equivalent task, content, states and configurations; select within delegated scope and record why. Continue a settled direction without reopening it.
- **Reproduction:** use [figma-ui](../figma-ui/SKILL.md) for Figma-led references. Preserve the existing brief, reference manifest, actual approval scope, frozen revision and captures. Judge fidelity separately from original quality.
- **Targeted repair:** isolate the reported defect and affected states/checks; preserve unrelated decisions and references. Repair the cause, rerun affected checks plus relevant regressions. An intentional reference change follows its existing approval/change policy.
- **Exploration:** deliver the requested alternatives at declared fidelity; do not claim implementation checks.

For original operational web work load [web-operational/v1](../../profiles/web-operational.md), then [searchable-collection-return/v1](../../patterns/searchable-collection-return.md) only if its preconditions hold. Read [the web workflow](../../docs/web-workflow.md) for state coverage, acceptance and evidence. Existing project systems win over generic guidance. Do not force a table or a visual style when the task contradicts its applicability; record the gap and project choice.

Build a representative slice, render it, inspect actual images, and test task outcomes before extending coverage. Complete the agreed states. Give independent critique the artifacts and acceptance criteria; repair substantiated blocker/major defects and rerun affected checks. Zero findings is valid with explicit coverage. Do not redesign for unsupported preferences or require the user to perform routine internal QA.

Use Figma for requested editable output, established Figma collaboration, or exact reference/component identity. Direct-to-code web iteration may use the same decision/acceptance contracts without a mandatory Figma step; browser evidence does not establish Figma identity.

Deliver the artifact, evidence tied to its current build and fixtures, and remaining limitations. Required FAIL/BLOCKED and exhausted budgets remain incomplete; NOT_APPLICABLE needs a contract-authorized condition and reason. Do not remove checks or rebaseline to pass. A local checker is bookkeeping, not a protected evaluator or automatic host enforcement. No blanket accessibility, quality-superiority, native-platform or cross-host claim follows from this web teaching fixture. Installation is explicit; repository edits do not change global skills.
